# ShadowSwap code audit

14 October 2026. Reviewed custom gameplay/UI scripts, input setup, build scenes,
and the phone, Shadow Sense, and Echo Mastery additions. Movement values, jump
force, room layouts, shadow duration, enemy damage, and optional badge targets
remain configured as before. Fixes below repair incorrect state and lifecycle
behavior rather than introducing new mechanics.

## Fixed

| Area | Bug | Change |
| --- | --- | --- |
| Ropes | Builder used an undefined `RopeGrab` tag; grabber expected `RopeEnd` | A `RopeGrabPoint` component identifies generated rope ends; legacy named tags remain supported |
| Rope chain | Existing anchor children could be mistaken for previous rope segments | Builder keeps the actual previous Rigidbody2D reference |
| Rope movement | Normal motor and rope both wrote velocity | Rope owns movement while attached; release disables the joint before deferred destruction |
| Keyboard input | E could swap and grab a rope together | E remains Swap; **F grabs ropes**; touch Grab is unchanged |
| Input asset | Float move input declared Vector2 | Move declares Axis; the generated wrapper is regenerated by Unity |
| Checkpoint retry | Lane, gravity, velocity, parent, rope/orb ownership, and pending input survived death | Respawn restores checkpoint lane/position and clears transient state |
| Gravity flips | Repeated entries stacked inversions; late coroutines could undo respawn state | One per-body timed effect refreshes on re-entry and restores its captured baseline |
| Upside-down platforming | Ground detection/jumping assumed downwards gravity | Ground checks and jump direction follow gravity; no extra jump ability was added |
| Buffered jumps | Render-rate timers could miss simulation steps or re-arm during takeoff | Buffer/coyote timers run with physics and a consumed ground jump cannot repeat before leaving ground |
| Health | Health/reference initialization happened after possible trigger callbacks; direct laser death missed HUD updates | Initialize in Awake; one death/reset notification per frame; restored hearts publish consistently |
| Orb transport | Disabled movement script and failed to release ownership reliably | Explicit carrier state blocks input, restores simulation on release, and releases on disable/respawn |
| Cutscenes | Used a global player and restored control without ownership/lifecycle cleanup | Lock the triggering player; register stop callback before Play; release on stop/disable/respawn |
| Swap safety | Ignored collider offset and omitted shadow hazards; zero cooldown caused invalid fill | Check translated collider bounds, include both hazard layers, and handle zero cooldown |
| Attached swapping | Teleport could stretch a rope joint across lanes or move a carried player | Valid rope swaps release the joint; orb/cutscene-owned players cannot swap |
| Platform parenting | Jumping/grabbing/swapping could keep the player attached to the previous moving platform | Release platform parenting when those actions transfer movement ownership |
| Lane objects | Hidden objects unsubscribed from the event needed to become visible again | Keep the listener until destruction and remove duplicate subscriptions |
| Campaign score | Repeated triggers/reloads/replays could count the same authored cookie again | Single pickup acceptance and per-campaign cookie identities; starting Play resets the campaign |
| Score subscriptions | Duplicate managers/scene callbacks could subscribe multiple times | Bind one player, unsubscribe on transitions/destruction, and install a manager for direct level testing |
| UI reliability | Missing labels/images/managers caused exceptions; score text rebuilt every frame | Guard missing references and update score text when the value changes |
| Inventory | Missing prefab could consume a box; repeated pickup callbacks could count twice | Validate before consuming and mark a picked-up box immediately |
| Walking audio | Handler ignored the `walking` argument | Use the requested walking state and tolerate missing clips/managers |
| Audio managers | Duplicate music managers survived; saved volume was applied too late; SFX could be scaled twice | Destroy duplicates, load saved settings in Awake, clamp volume, and apply SFX gain once |
| Audio UI/hints | Missing slider/player/text/source references and leaked slider handlers | Safe fallback binding and matching listener cleanup; orb audio respects SFX volume |
| Arrow hints | Orb event called lifecycle method directly, with dangling callbacks and unowned fades | Dedicated completion callback, unsubscribe, and owned fade cleanup |
| Enemies/hazards | Octopus changed physics velocity at render rate; missing patrol/laser/path references crashed | Physics-rate chase/jump, prevent repeated takeoff impulses, and validate optional references |
| Navigation | Multiple collisions could queue reloads; invalid next scenes and paused transitions were unsafe | One guarded scene loader validates build destinations and clears input/pause on accepted loads |
| Results/mobile UI | Result card could exceed safe area; disabled custom buttons still accepted presses | Scale result card to fit and respect CanvasGroup/Button interaction state |
| Mastery records | Invalid external summary values could be saved | Validate finite, nonnegative, consistent values before writing |

## Behavior to know

- **F** now grabs a rope; **E** swaps. Space still jumps/releases, W/S climb,
  A/D move, 1/2 place boxes, and Escape pauses.
- Replaying a room still allows collecting cookies for that attempt's Collector
  badge. The same authored cookie increases campaign score once per campaign.
  Starting Play from Main Menu starts a new campaign; mastery records persist.
- Default cookie identities are cached from the scene path and authored hierarchy
  before pickup. Optional explicit `Persistent Id` values can be assigned for
  custom content; keep them unique within a scene. This is campaign accounting,
  not a paid currency or cloud save system.
- Full-reload hazards still restart the room. Health/laser deaths still use the
  checkpoint. Their authored retry policies are preserved; checkpoint cleanup is
  now complete. This audit does not roll back movable puzzle objects on death.
- Gravity re-entry refreshes one inversion; it no longer toggles randomly due to
  overlapping coroutines. Restoring/respawning cancels the temporary inversion.
- A valid swap while hanging releases the rope while preserving momentum.
  Carried/cutscene-owned players regain gameplay control when that owner releases.
- Level 3's authored `RopeAnchor` is currently inactive. That scene setting is
  preserved; activate it in the Inspector when you want the rope in the level.
  The validation enables it temporarily to exercise the real prefab and grabber.

## Validation

Validated with Unity 6000.3.26f1:

- **52 new behavior checks** covering state cleanup, ropes, gravity, scoring,
  missing references, audio, control ownership, and invalid data/navigation.
- **140 existing native regression checks** for phone controls, Shadow Sense,
  and Echo Mastery.
- **14 Play Mode checks** exercising all three gameplay scenes, rope prefab
  building/grabbing, exits, replay, completion pause, FinishScene, and MainMenu.
- **602 scene objects** across all five enabled build scenes checked for missing
  scripts; none were found.
- The final Play Mode run produced no captured errors/exceptions/assertions.
  Test record keys were deleted and the existing motion preference was restored.
- The complete script set compiles against the installed Unity assemblies.

Scene layout assets were not rewritten. The inactive Level 3 rope was enabled
only within the test run, and active cutscene/orb ownership was released before
testing its grabber. The exit callbacks were invoked by the harness; these are
targeted smoke and behavioral tests, not complete puzzle playthroughs. Android
Build Support/device testing and performance profiling remain outstanding.
